# 拉片超人

> 这是私人 Studio 仓库，用于内部研发、发布前验证和私人工作流记录。可公开复用的核心代码维护在 [cd112233/lapian-chaoren](https://github.com/cd112233/lapian-chaoren)；不要把本仓库直接改为公开。边界和同步规则见 [STUDIO.md](STUDIO.md)。

把打斗参考视频拆成可重制、可审核、可交接的镜头工程。

当前版本：`v0.4.0`。复刻对比不再把单帧或自动切镜当作复刻目标，而是优先核对完整因果事件：进入状态、动作发展、接触/峰值、受力反应和离开桥接。

它不只回答“画面里有什么”，而是把每个镜头拆成：

- 切点与前后镜连续性
- 角色位置、肢体动作和动作分拍
- 力量来源、接触点与受力响应
- 机位、运镜、焦段、焦点与剪辑意图
- VFX 层级、交互光、环境反馈与声音节拍
- 不确定项、容易漏写项和重制路线

仓库不包含任何原片、商业角色素材或个人项目输出。

## 核心能力

### 1. 自动建立镜头骨架

`src/analyze_reference.py` 使用 FFmpeg、PySceneDetect、Pillow 和 OpenTimelineIO：

- 读取视频元数据
- 自动检测候选切点
- 导出首帧、中间帧、尾帧和接触表
- 按镜头切分独立视频片段
- 输出 CSV、YAML、Markdown 和 OTIO

### 2. 人工或 AI 深化拉片

使用 `templates/` 中的字段表与审核提示词，继续补足摄影、动作、力学、VFX、声音和镜间因果。

### 3. 逐镜审片工作台

`src/build_review_page.py` 把深化后的 YAML 生成一个无需服务器、可直接打开的 HTML 审片工作台：

- 视频、逐帧接触表和首中尾对照
- 识别横屏、竖屏、方屏和超宽屏；监看区、首中尾布局和移动端审核方式按素材画幅自动调整
- 接触表与总览图完整保留源画面边缘，不用裁切换取“铺满”
- 镜头搜索与状态筛选
- 事实、判断、不确定项分层
- 前后镜因果链
- 人工备注和审核清单
- 待审、问题、已确认状态
- 字段覆盖率、自动质量诊断与人工确认度
- 下一诊断、下一未确认和诊断字段直达
- 动作、摄影机、接触力学、VFX、声音、风险全局泳道
- 战斗强度、生成难度与连续性风险曲线
- 审核 JSON、完整 Markdown、问题清单 Markdown 导出
- 单镜 AI 返修任务导出，以及带 `shot_id` 校验和差异预览的安全导回
- 当前镜头 AI 影像导师：支持口语化提问、专业术语辨认、多轮追问与流式回答
- 摄影机、构图、灯光、色调、后期调色、质感合成、动作、剪辑和 VFX 专项知识
- 浏览器本地保存、AI 修订历史与原始描述恢复
- 字号、界面密度、面板宽度和影院模式

### 4. 人机学习闭环

- 把本地视频拖入片库后，自动完成切镜、抽帧、逐镜切片和学习页生成
- 导入时自动探测容器、编码和音频轨道；兼容文件直接使用，必要时本地生成标准 H.264/AAC/yuv420p MP4，原片副本保留
- 自动读取 `rotate` / Display Matrix 方向元数据；带旋转标记的文件会在本地烘焙正确方向并转为方形像素，避免竖片被误判为横片
- 支持 MP4、MOV、MKV、AVI、WebM、M4V、WMV、FLV、TS/MTS/M2TS、3GP、MPG、OGV、VOB、MXF、RM/RMVB 等常见视频容器
- AI 初拉按字段返回内容、可信度和证据，不用一段散文代替可核查结果
- 学习、盲审和效率三种审核模式
- 保存 AI 原判断、人工判断、最终结论、纠错原因和证据
- 只有人工主动晋级的内容才进入可信知识
- 代表镜头复刻任务、结果文件信息、五项评分和失败经验回流
- 完整学习工程 JSON 导出与恢复

### 5. 全片复刻对比

每个已完成的原片项目都可以继续导入一段复刻视频：

- 自动适配复刻片格式并重新检测候选切点。
- 主轨把多个镜头合并为完整因果事件，按进入、发展、峰值、反应和离开连续播放；帧图只负责定位证据。
- 每个事件保存必须保持项、容许误差、直接失败条件、可观察差异、观感影响、根因和下一版动作。
- 机械辅轨继续用单调序列对齐区分一一对应、原片缺失和复刻新增候选镜头，支持人工修正。
- 比较镜头数量、时长、归一切点漂移，以及运动、亮度和声音的候选峰值相位，但不把这些信号命名为真实动作。
- 双视频支持并排、A/B 和透明叠加，按真实时长或镜头阶段同步播放。
- 每组机械镜头仍保留开场、中段、候选峰值、收势和下一镜桥接证据，供排查切点与事件边界。
- 按节奏、构图、动作与力学、摄影机、VFX/灯光/色调、声音和连续性审核。
- 自动发现只作为工程数据证据，不使用角色替换后的像素差充当质量分。
- 修复队列合并根因；电影技术术语独立记录为“已观察 / 特征匹配 / 工程验证 / 无法确认”。

完整边界与数据结构见 [复刻对比工作台](docs/remake-comparison.md)。

自动质量分是用于排查遗漏的启发式信号，不替代对原始画面的人工判断。页面会重点检查逐帧证据、具体肢体、力向、变焦/运镜、VFX 时序、分身数量和前后镜桥接。

## 快速开始

### 环境要求

- Python 3.10+
- FFmpeg / ffprobe

```bash
git clone https://github.com/cd112233/lapian-chaoren.git
cd 拉片超人
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 推荐入口：本地片库

```bash
make workbench
```

浏览器会打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。拖入视频后，本地服务会依次生成：

- 从片源保存、逐帧切镜、逐镜证据到审片页生成的实时进度。
- 当前阶段、已扫描时长或正在处理的镜头序号。
- 带二次确认的本地项目删除；正在上传或分析的项目会被保护。
- 顶部“保存位置”可切换项目片库目录；支持手动绝对路径和系统文件夹选择器，旧目录中的项目不会被迁移。
- 导入阶段会显示“格式检查 → 自动适配 → 切镜分析”的连续进度；兼容且无需烘焙方向的 H.264 MP4/MOV 不会被重复转码。
- 项目完成后显示“竖屏 · 9:16 · 1080×1920”等素材信息；审片页对普通横屏、竖屏、方屏和超宽屏使用不同监看与首中尾布局。
- 项目行的“复刻对比”可导入多个复刻版本，实时查看处理进度，并分别打开或删除。

```text
outputs/projects/<project-id>/
├── project.json
├── source/
│   ├── <原始片源>
│   └── analysis_source.mp4       # 仅在需要适配时生成
├── analysis/
│   ├── metadata.json
│   ├── shots.csv
│   ├── shot_manifest.yaml
│   ├── learning_shots.yaml
│   ├── review.html
│   ├── clips/
│   └── shots/
└── comparisons/
    └── <comparison-id>/
        ├── comparison.json
        ├── comparison.html
        ├── source/
        ├── analysis/
        └── evidence/
```

处理和媒体访问都限制在本机 `127.0.0.1`。原片与生成项目位于片库保存位置，不会进入 Git。
`make` 会优先使用项目已有的 `.venv/bin/python`，未创建虚拟环境时才回退到系统 `python3`。

首次启动默认使用 `outputs/projects`。在片库页面点击顶部“保存位置”即可改到任意有读写权限的文件夹；设置保存在 `~/.config/lapian-chaoren/settings.json`（可用 `LAPIAN_SETTINGS_PATH` 覆盖）。启动参数 `--projects-root` 具有最高优先级，并会锁定网页编辑。旧位置不会自动迁移，想切回时再次选择旧目录即可。

需要体验 AI 初拉或影像导师时，在第二个终端启动可选 AI 服务：

```bash
make advisor-workbench
```

这会使用不做视觉推理的 `mock` 模式，并自动跟随片库页面当前的保存位置读取项目帧图。显式传入 `--asset-root` 或设置 `AI_ADVISOR_ASSET_ROOT` 时则固定使用指定目录。真实模型配置见后文；不启动此服务不影响上传、自动切镜、人工拉片、审核和导出。

### 命令行入口

#### 第一步：分析参考视频

```bash
python src/analyze_reference.py /absolute/path/reference.mp4 \
  --output outputs/reference_fight \
  --detector adaptive \
  --split-clips
```

产物示例：

```text
outputs/reference_fight/
├── metadata.json
├── shots.csv
├── shot_manifest.yaml
├── reference_timeline.otio
├── report.md
├── overview_contact_sheet.jpg
├── clips/
└── shots/
    └── SH001/
        ├── start.jpg
        ├── middle.jpg
        ├── end.jpg
        └── contact_sheet.jpg
```

> 自动切镜只是候选结果。快速甩镜、闪白、爆炸、粒子遮挡和渐变必须人工复核。

> 画幅证据默认完整保留。抽帧、接触表、总览图、视频片段和网页监看都使用 contain/letterbox；不会为了填满 16:9 容器裁掉竖屏或超宽屏边缘。

#### 第二步：深化镜头描述

参考：

- `templates/shot_breakdown_fields_v2.md`
- `templates/manual_review_prompt.md`
- `examples/demo/demo_shots.yaml`

媒体路径应相对于最终生成的 HTML 文件。

#### 第三步：生成审片工作台

```bash
python src/build_review_page.py \
  examples/demo/demo_shots.yaml \
  --output examples/demo/review_demo.html
```

然后直接打开：

```text
examples/demo/review_demo.html
```

#### 第四步：启动 AI 影像导师与 AI 初拉

不配置真实模型也可以先用内置模拟模式体验完整交互：

```bash
python3 src/ai_advisor_server.py \
  --provider mock \
  --asset-root examples/demo
```

AI 默认关闭。先在“舒适度 → AI 影像导师”中选择“启用”，再点击镜头栏的“问 AI”或按 `A`。关闭时入口会隐藏，也不会检查服务或发起 AI 网络请求，普通拉片完全独立运行。真实模型、Ollama、视觉帧图和安全配置见 [AI 影像导师文档](docs/ai-film-advisor.md)。API Key 只放在本地服务环境变量中，不写入 HTML。

AI 启用后，“学习”页签可执行当前镜头初拉。内置 `mock` 只验证接口和审核流程，并明确标记低可信度；真实画面分析需要配置支持视觉输入的模型。

## 三种学习模式

| 模式 | 审核顺序 | 用途 |
|---|---|---|
| 学习 | 先看 AI，再接受或纠正 | 熟悉术语和区分依据 |
| 盲审 | 先写人工判断，再揭示 AI | 测量独立阅片能力 |
| 效率 | 只显示低可信、诊断和未决字段 | 提高大量阅片速度 |

如果某镜已经展示过 AI，再切换到盲审，系统会将其标记为“看过 AI 后的判断”，不计入有效盲审指标。

## 审片快捷键

| 快捷键 | 功能 |
|---|---|
| `J` / `↓` | 下一镜 |
| `K` / `↑` | 上一镜 |
| `Space` | 播放 / 暂停 |
| `F` | 标记问题 |
| `C` | 确认并进入下一镜 |
| `T` | 影院模式 |
| `G` | 全局动作与生产诊断 |
| `A` | 打开当前镜头 AI 影像导师 |
| `/` | 聚焦搜索框 |

## AI 单镜返修闭环

1. 在镜头标题栏点击“本镜 AI”，导出只包含当前镜头的返修任务 JSON。
2. 将任务交给可读取帧图或视频的模型处理。
3. 从“导出审核 → 校验并导入当前镜头 AI 结果”粘贴或读取返回 JSON。
4. 页面强制核对 `shot_id`，先显示字段级差异，再选择“只填空白 / 追加 / 替换”。
5. 导入后的镜头自动回到待审核；替换和恢复原始描述均有二次确认。

AI 返回建议格式：

```json
{
  "shot_id": "SH018",
  "patch": {
    "camera_motion": "固定低机位，主体位移造成尺寸变化；无推镜。",
    "vfx_layers_timing": "F0501 风环增强，F0505 接触前达到峰值，命中后向画面右侧消散。"
  }
}
```

## 推荐生产顺序

1. 自动生成完整镜头表。
2. 人工校正切点。
3. 选最难的 6—10 秒作为黄金测试段。
4. 建立角色身份包与场景规则。
5. 分别审核角色动作、摄影机和特效复杂度。
6. 先做低模动作及摄影机预演。
7. 通过后再替换高质量角色和场景。
8. 从 6—10 秒扩至 20—25 秒，最后才扩满全片。

## 数据与版权边界

- `outputs/`、原视频、音频和角色参考图默认不进入 Git。
- 上传参考素材前，请确认你拥有分析、存储和再创作权限。
- 公开发布时应重新设计原创动作、角色、场景、声音和特效，而不是直接复制商业成片。
- 自动分析只能提供证据和候选判断，不能替代人工导演审核。
- AI 对话和 AI 初拉不会自动进入可信知识；人工结论必须填写纠错原因与证据后主动晋级。
- 单镜代表性复刻仍可使用审片页内的轻量评分；全片复刻视频、镜头对应、审核和修复队列则保存在项目的 `comparisons/` 目录中，可持续复核。
