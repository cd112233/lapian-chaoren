# 复刻对比工作台

复刻对比回答三个问题：哪里不像、影响什么、下一版具体改什么。它不生成一个总分，也不把角色替换后的像素差当成质量结论。

## 使用流程

1. 在片库中完成原片分析。
2. 点击项目行的“复刻对比”，导入一段复刻视频。
3. 系统完成格式适配、复刻片切镜、视听候选峰值提取和镜头单调对齐。
4. 人工先核对镜头对应，再逐组审核关键节点和七个固定维度。
5. 把重复症状合并成根因，加入修复队列。
6. 下一版复刻完成后建立新的对比记录，不覆盖旧版本。

## 主轨：可观察结果

固定审核维度：

- 节奏
- 构图
- 动作与力学
- 摄影机画面效果
- VFX、灯光、色调
- 声音
- 镜间连续性

每条有效差异应包含：

```text
原片事实
复刻事实
可见差异
观感影响
严重度
修改建议
证据时间段或节点
结论等级
```

机械分析可以确认镜头数量、镜头时长、归一切点漂移和信号峰值时间；它不能独立确认“这是变焦”“这是重击接触”“这是景深变化”。

## 关键节点

每组镜头至少保留：

- 开场状态
- 中段检查点
- 收势与下一镜桥接

系统还会用低分辨率视听信号定位最多三个候选峰值：

- 运动变化峰值候选
- 亮度 / VFX 变化候选
- 声音峰值候选
- 视听联合峰值候选

候选峰值只帮助找到需要复核的时间段。使用者仍需把它改名为真实动作阶段，例如启动、方向变化、接触、重击峰值、反应或消散；证据不足时保留“无法确认”。

## 镜头对应

自动对应采用保持时间顺序的序列对齐：

- 一对一对应
- 原片镜头在复刻中缺失
- 复刻片新增镜头

时长占比和全片位置用于自动匹配，不参与艺术评分。人工修正时，每个原片镜头最多选择一个复刻镜头，复刻镜头不能重复或倒序。

镜头对应改变后，系统只把审核记录迁移到“原片镜头 ID + 复刻镜头 ID”完全相同的新对应。无法安全迁移的逐镜审核不会被悄悄挂到另一组镜头上。

## 辅轨：电影技术鉴定

术语学习与主差异判断分开保存，证据等级固定为：

1. `已观察`
2. `与某技术特征匹配`
3. `有工程数据验证`
4. `无法确认`

技术名称不参与自动评分，也不会因为新手和单个 AI 同时同意就自动进入可信知识。

## 播放方式

- **并排**：同时保留原片和复刻画面。
- **A/B**：在同一显示区域切换两条视频。
- **叠加**：用透明度核对构图、屏幕方向和运动轨迹。
- **按镜头阶段同步**：把两个不同时长镜头的 0%—100% 阶段对齐。
- **按真实时长同步**：两条视频使用相同播放速度，直接暴露时间差。

横屏、竖屏、方屏和超宽屏都使用 `object-fit: contain`，不裁切影视证据。

## 项目结构

```text
comparisons/<comparison-id>/
├── comparison.json
├── comparison.html
├── source/
│   ├── <复刻原文件>
│   └── analysis_source.mp4
├── analysis/
│   ├── metadata.json
│   ├── shots.csv
│   ├── comparison_signals.json
│   ├── clips/
│   └── shots/
└── evidence/
```

`comparison.json` 保存自动对应、关键节点、机械发现、人工审核、技术鉴定和修复队列。原片、复刻片和证据都留在本地项目目录，不进入 Git。

## 本地 API

```text
POST   /api/projects/<project-id>/comparisons
GET    /api/projects/<project-id>/comparisons
GET    /api/projects/<project-id>/comparisons/<comparison-id>
PUT    /api/projects/<project-id>/comparisons/<comparison-id>/alignment
PUT    /api/projects/<project-id>/comparisons/<comparison-id>/review
DELETE /api/projects/<project-id>/comparisons/<comparison-id>
```

视频继续使用原始请求体上传；文件名和对比名称通过请求头传入。处理中的对比会阻止项目删除和片库位置切换。

## 当前边界

- 自动切镜和自动对应都需要人工复核。
- 候选峰值不等于动作事件或电影术语。
- 第一版不做角色语义、骨架接触、光流相机解算或镜头光学参数反演。
- 没有 AI 服务时，上传、比较、审核、保存和修复队列仍完整可用。
- AI 后续可以读取同一证据结构提出建议，但不能越过结论等级和人工确认边界。
