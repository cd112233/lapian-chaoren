# 复刻对比工作台

复刻对比回答三个问题：哪里没有成立、它影响了什么、下一版具体改什么。系统不生成一个抽象总分，也不把角色替换后的像素差、随机粒子位置或自动切镜数量当作质量真值。

## 为什么不再逐帧复制

角色、场景、毛发、布料、烟尘和粒子天然会变化。逐帧对齐容易把“外观不同”误判为失败，也会把“动作因果错误但某一帧相似”误判为成功。

默认比较单位因此改为一段完整因果事件：

```text
进入状态 → 动作发展 → 接触 / 峰值 → 反应结果 → 离开与下一段桥接
```

静帧仍用于定位证据；自动切镜仍用于排查节奏与边界，但两者都不是复刻验收目标。

## 使用流程

1. 在片库中完成原片分析。
2. 点击项目行的“复刻对比”，导入复刻视频。
3. 系统完成格式适配、候选切点检测、视听信号提取和机械镜头对齐。
4. 把相关镜头合并为关键事件段，写入原片与复刻的连续时间窗。
5. 优先在“关键事件”主轨审核五个阶段，再用“机械切镜”辅轨核对误切、漏切和边界。
6. 把重复症状合并为根因，加入修复队列。
7. 下一版复刻建立新的对比记录，不覆盖旧版本。

## 主轨：关键因果事件

每个事件保存：

- 原片与复刻的连续起止时间。
- 进入、发展、峰值、反应和离开五个阶段窗口。
- 原片每阶段必须成立的真实画面。
- 复刻片中实际观察到的动态差异。
- 必须保持项、容许误差和直接失败条件。
- AI 初判、人工纠正、观感影响、最可能根因和下一版动作。
- 对应生成分段、提示词追溯和连续证据总览。

有效结论应按以下顺序书写：

```text
原片事实 → 复刻事实 → 可见差异 → 观感 / 叙事影响 → 根因 → 下一版动作 → 验收结果
```

### 必须保持项

必须保持的不是像素，而是事件规则，例如：

- 谁是主动者、谁是被动者。
- 事件先后顺序是否正确。
- 空间距离是否连续缩短或扩大。
- 接触点、支撑点、力向和受力反应是否自洽。
- 摄影机意图、屏幕方向和结果构图是否成立。
- VFX 是否在正确作用点出现、增强、交互并消散。
- 离开状态能否无矛盾地接入下一段。

### 容许误差

只要不破坏上述规则，以下内容通常可以浮动：

- 毛发、衣物和雪尘的次级运动。
- 随机粒子的精确位置和数量。
- 不影响动作峰值的细小表演差异。
- 角色替换后不可避免的轮廓、纹理和局部色彩变化。

### 直接失败条件

以下问题不能被单帧相似度或全片总时长接近掩盖：

- 关键动作缺失、顺序颠倒或主动 / 被动关系反转。
- 接触没有发生，或受力方向与前因不一致。
- 空间关系从上下包夹变为同平面左右攻击。
- 横向能量被硬切成竖向结果，中间没有连续改向过程。
- 角色瞬移、缩小或硬切替代了原片要求的消散、吸附或位移过程。
- 下一段重复上一段结果，造成动作相位整体后移。

## 辅轨：机械切镜

自动切镜只是一条机械基线：

- 一对一候选对应。
- 原片候选镜头缺失。
- 复刻片出现额外候选镜头。
- 镜头时长、归一切点漂移和视听变化峰值。

爆光、闪帧、快速 VFX 和运动模糊可能被误拆成多个镜头，因此候选数量不能直接解释为“复刻多了多少镜”。人工修正时，每个原片镜头最多选择一个复刻镜头，复刻镜头不能重复或倒序。

镜头对应改变后，系统只迁移“原片镜头 ID + 复刻镜头 ID”完全相同的逐镜审核。事件审核按稳定事件 ID 保存，不会因为机械镜头重新编号而串写。

## 播放与审核

- **并排**：同时观察构图、角色距离、屏幕方向和环境反馈。
- **A/B**：在同一监看区域快速切换。
- **叠加**：核对主体位置、运动轨迹与画面中心；不能用于角色轮廓像素评分。
- **按阶段同步**：让两个不同时长的事件窗口在 0%—100% 阶段同时结束。
- **按真实时长同步**：两条视频使用相同播放速度，直接暴露动作快慢和停顿差异。
- **完整事件播放**：连续查看事件前因与结果。
- **阶段窗口播放**：单独循环进入、发展、峰值、反应或离开，不脱离上下文看一张帧。

横屏、竖屏、方屏和超宽屏均使用 `object-fit: contain`，不裁切影视证据。

## 七维审核

事件主轨确认因果是否成立后，机械镜头辅轨可继续细查：

1. 节奏。
2. 构图。
3. 动作与力学。
4. 摄影机画面效果。
5. VFX、灯光与色调。
6. 声音。
7. 镜间连续性。

运动、亮度和声音曲线只能定位候选时间段；它们不能独立确认“这是重击”“这是变焦”“这是拉焦”或“这是某种特效”。

## 电影技术鉴定辅轨

术语学习与主差异判断分开保存，证据等级固定为：

1. `已观察`
2. `与某技术特征匹配`
3. `有工程数据验证`
4. `无法确认`

技术名称不参与自动评分，也不会因为新手和单个 AI 同时同意就自动进入可信知识。

## 修复队列

机械差异和事件症状不能逐条堆成任务。修复队列只保留能指导下一版制作的共同根因，例如：

- 生成单位过大，单段同时承担过多镜头和动作阶段。
- 缺少三维 blocking、骨架姿态、接触点或摄影机路径控制。
- 动作、角色一致性和 VFX 一次烘焙，导致特效遮住作用关系。
- 场景参考不足，空间被模型重建为通用雪地。
- 画幅不一致，2.35:1 的负空间被 16:9 紧构图破坏。
- 分段首尾重复，造成局部事件相位后移。

下一版优先修完整因果链，再修材质、粒子和细节。不要用继续堆长提示词替代空间控制和分层制作。

## 数据结构

```text
comparisons/<comparison-id>/
├── comparison.json
├── comparison.html
├── source/
│   ├── <复刻原文件>
│   └── analysis_source.mp4
├── analysis/
│   ├── metadata.json
│   ├── shots.csv
│   ├── comparison_signals.json
│   ├── clips/
│   └── shots/
├── event_evidence/
└── evidence/
```

`comparison.json` 保存机械对应、关键事件、AI 初判、人工审核、技术鉴定和修复队列。原片、复刻片、提示词、角色图和证据都留在本地项目目录，不进入 Git。

## 本地 API

```text
POST   /api/projects/<project-id>/comparisons
GET    /api/projects/<project-id>/comparisons
GET    /api/projects/<project-id>/comparisons/<comparison-id>
PUT    /api/projects/<project-id>/comparisons/<comparison-id>/events
PUT    /api/projects/<project-id>/comparisons/<comparison-id>/alignment
PUT    /api/projects/<project-id>/comparisons/<comparison-id>/review
DELETE /api/projects/<project-id>/comparisons/<comparison-id>
```

`events` 接口校验事件和阶段时间窗不能越过各自视频，也会在事件 ID 变化后丢弃无法安全关联的旧事件审核。写入成功后重新生成对比页面。

## 当前边界

- 自动切镜、事件边界和镜头对应都需要人工复核。
- 系统不会自动反演角色骨架接触、完整三维摄影机或真实镜头光学参数。
- AI 初判可以帮助发现问题，但不能越过证据等级和人工确认边界。
- 没有 AI 服务时，上传、播放、事件审核、机械镜头核对、保存和修复队列仍完整可用。
- 事件级对比解决“比较什么”的问题；复杂动作能否重现，仍取决于三维预演、姿态控制、分层生成和后期合成。
