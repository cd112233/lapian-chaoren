# 公开与私人数据边界

拉片超人采用三层结构，避免把工具源码、个人知识和大型媒体混在同一个 Git 仓库中。

## 公开核心

公开仓库包含：

- 切镜、抽帧、项目生成与本地片库程序。
- 审片工作台、AI 可选网关和通用审核流程。
- 通用字段表、基础系统提示词、合成示例与自动测试。
- 架构、使用和贡献文档。

公开版必须能独立运行，不依赖任何私人仓库。

## 私人知识

以下内容应放在独立私有仓库或私人知识库中：

- 真实项目的可信知识卡、人工纠错记录与审核导出。
- 角色设定、场景规则、生产提示词和模型路由配置。
- 复刻评分、失败案例和未公开的方法实验。
- Obsidian 笔记与内部项目索引。

私人层可以调用公开核心，但公开核心不能引用私人路径或数据。

## 本地媒体

原片、帧图、逐镜片段、音频和复刻视频不建议进入任何普通 Git 仓库。使用独立目录，并在启动时显式配置：

```bash
export LAPIAN_PROJECTS_ROOT="$HOME/Movies/LapianProjects"
export AI_ADVISOR_ASSET_ROOT="$LAPIAN_PROJECTS_ROOT"
```

即使文件已经被 `.gitignore` 排除，也不要使用 `git add -f` 强制提交。

## 发布检查

公开发布前至少确认：

1. 没有个人绝对路径、API Key、真实模型地址或内部仓库链接。
2. 没有未经授权的原片、截图、角色图、声音或复刻结果。
3. 示例资产为原创或明确可再分发，并记录来源。
4. `outputs/`、`.env`、`private/`、`studio/` 和本地知识目录未被跟踪。
5. 测试、静态检查和 GitHub Actions 均通过。
